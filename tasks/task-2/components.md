1. `UserController` (Слой `web`):
    * Область ответственности: Точка входа для всех HTTP-запросов, связанных с пользователями (регистрация, логин, возможно получение данных текущего пользователя). Принимает DTO, делегирует обработку
      бизнес-логике.

2. (пока опустим) `KeyController` (Слой `web`):
    * Область ответственности: Предоставление публичного ключа user-service через эндпоинт /.well-known/jwks.json. Его основной потребитель — API Gateway.

3. `UserService` (Слой `service` - бизнес-логика):
    * Область ответственности: Управление жизненным циклом сущности User. Это основной сервис для всех операций (CRUD), связанных с пользователями. Вся логика работы с паролями (хеширование и проверка)
      находится здесь.
    * Задачи: Регистрация пользователя, поиск пользователя по id/email, проверка учетных данных (checkCredentials).
    * Границы: Работает только с данными пользователя и репозиторием.

4. `AuthService` (Слой `service` - бизнес-логика):
    * Область ответственности: Оркестрация процесса аутентификации пользователя (входа в систему).
    * Задачи: Принимает учетные данные, через UserService проверяет их валидность, и если все верно, запрашивает генерацию токенов у JwtTokenService.
    * Границы: Является координатором между контроллером, UserService и JwtTokenService. Не имеет прямой зависимости от PasswordEncoder.

5. `JwtTokenService` (Слой `service` - бизнес-логика):
    * Область ответственности: Все, что связано с созданием и управлением JWT (Access и Refresh токенов).
    * Задачи: Генерация токенов на основе данных пользователя, их подпись приватным ключом.
    * Границы: "Криптографический" сервис, не знающий о бизнес-логике пользователя или базе данных.

6. (пока опустим) `KeyService` (Слой `service` - бизнес-логика):
    * Область ответственности: Управление криптографическими ключами.
    * Задачи: Загрузка и предоставление текущей пары RSA-ключей (приватного и публичного).
    * Границы: Безопасно поставляет ключи для JwtTokenService и KeyController.

7. `UserRepository` (Слой `repository`):
    * Область ответственности: Прямое взаимодействие с базой данных для сущности User через Spring Data JPA.

8. `User` (Слой `domain`):
    * Область ответственности: Представление сущности пользователя в доменной модели, мапится на таблицу БД, реализует UserDetails.
